# 識別子の可読性と名称変更の運用

**対象範囲:** C++ソースのクラス名・関数名・変数名・定数名、ソースファイル名、include、ビルド設定、既存のリネームスクリプト。実際の変更対象はコードとビルド設定を正本とする。

## 基本方針

- ドイツ語由来で意味が推測しにくい名前、旧綴り、英語名との混在を、可読性改善の優先候補とする。
- 名前変更は処理内容のリファクタリングと切り離して実施し、挙動を変えない。
- まず同じ責務の最新実装や既存用語を確認し、意味の正確さ・一貫性・理解しやすさを基準に候補を選ぶ。
- StandardやExtendedとの名称一致を目的にしない。Plus/Expert向けコードで理解しにくい名称が残っている場合、機械的に踏襲する必要はない。
- 識別子の名前だけの違いと処理内容の違いを混同しない。処理が同じでも名前は可読性のために変更してよい。
- 変更候補はユーザーのレビューを受ける。未承認の候補を大規模一括置換しない。

## 対象コードで確認した例

以下は調査上の候補であり、置換の承認を意味しない。

| 現行名称 | 意味・課題 | 変更候補 | リスク |
|---|---|---|---|
| `dataobj/koord.h` / `koord` | 座標型に関するドイツ語表記 | `coordinate` | 広範な型・演算子・テンプレート参照 |
| `dataobj/ribi.h` / `ribi` | コメントで `Richtungs-Bit` と説明される方向ビット表現 | `direction_bits` など | 方向と斜面の型が同じヘッダーにある |
| `boden/grund.h` / `grund_t` | 地面タイル基底クラス。コメントにもドイツ語が残る | `ground_tile_t` | 基底クラス・派生型・型特性・シリアライズ経路の参照 |
| `karte_t` | ワールド全体を管理する中心クラス | `world_t` など | 呼び出し箇所が多数あり、型名・シンボル・ドキュメントの更新が必要 |
| `perlin_hoehe` | 地図生成の高さ計算 | `perlin_height` | オーバーロードと呼び出し元の確認が必要 |
| `simconvoi.*`, `convoihandle_t.h` | `convoi` と `convoy` の綴りが混在 | 英語綴りへの統一 | ソース・ヘッダー・プロジェクト・外部スクリプトを確認 |
| `boden/wege/schiene.*`, `strasse.*`, `kanal.*` | ディレクトリ名や型名にドイツ語が多い | `track`, `road`, `canal` など | 大規模なパス変更、MSVC/CMake/Makefileの更新 |

## 置換スクリプト

`rename_identifiers.py` と `rename-rules.json` は、明示された識別子の完全一致置換と、同じトークンによるパスの変更を行うための共通ツールとする。

- 既定はプレビューであり、`--apply` が指定された場合にのみファイルを書き換える。
- ルール集合は空から始める。対象ごとの意味・使用箇所・外部連携を調べ、承認されたルールだけを追加する。
- 両リポジトリでまずプレビューし、差分が一致しない場合は、存在するコードやビルド設定の違いを調査してから適用する。
- 短い識別子や一般語は文字列・コメント・外部データにも一致し得る。C++構文を理解するツールではないため、差分を人が確認する。
- ファイルパス変更時は、CMake、Makefile、Visual Studioのプロジェクトとフィルター、生成スクリプト、CI、テスト、ドキュメント内リンクも確認する。
- 置換前に作業ツリーをクリーンにし、適用後は検索結果・差分・全ビルド設定・テストを確認する。

## 可読性の他の課題

- 同じ概念を示す英語表記とドイツ語由来表記の混在。
- 意味の説明がコメントの一部にしかなく、クラス／関数名から責務が分からない箇所。
- 変数名が `pos`、`k`、`n` など短く、座標系・単位・所有者・有効範囲が判別できない箇所。ただし頻繁に呼ばれる処理や既存のスタイルも考慮し、機械的な変更はしない。
- 古いコメント、スペルミス、誤ったコピーコメント。コードの実際の動作と照合してから訂正する。
- 巨大な関数や複数責務の関数。特に性能上重要な処理は、可読性改善のみを理由に呼び出し回数・仮想関数呼び出し・メモリアクセスを増やさない。
- 歴史的に保存形式・ネットワーク・pak・翻訳キー等に意味を持つ名称。コード内識別子の改名と外部形式の変更を区別する。

## 未解決の問い

- まず優先して改名する識別子の一群をどれにするか。
- ファイル／ディレクトリ名を型名と同時に変更するか、型・関数の改名を先行させるか。
- 外部のpak、シナリオ、翻訳、AIスクリプトが参照する文字列をどこまで対象にするか。
- より正確な参照更新のために clang-based tooling 等を導入するか。導入前にビルド環境と既存依存関係を確認する。
